## PART B — THE FOUR WORK UNITS

### WORK UNIT 1 — An explicitly requested slot must NEVER be silently swapped

**R1.1** When `--slot` was given, the dispatch MUST use exactly that slot. If it is not
usable (busy / at the registry cap / not signed in), the dispatch MUST stop with the named
code - `EXIT_SLOT_BUSY` for busy, `EXIT_NOT_SIGNED_IN` for unsigned - and report it. It
must NOT pick another account. (Round 21 FIX 2 already says busy is not rotatable; make the
inner policy obey it.)

**R1.2** `_pool_slots_in_order()` must not re-sort an explicitly requested slot out of the
first position. Either the requested slot is returned first, or the caller refuses - never
a silent substitution. The registry-load ordering is still useful for the AUTOMATIC policy
(when no slot was requested); keep it there.

**R1.3** The log must never claim `explicitly requested slot X` when X was not the requested
slot. When a substitution happens (only allowed for the automatic policy), print one line
in this shape:

```
[+] requested slot /u/1/ -> using /u/2/ because <reason> (registry load /u/1/ = 2/2, /u/2/ = 0/2)
```

**R1.4** Every substitution prints BOTH slots' registry load and the reason.

**R1.5** The ladder's existing `Rotating to next pool account (n/N)` line must also carry the
reason and the load.

**R1.6** The line `Account actually used by this lane: <email> (/u/N/)` must stay and must be
printed BEFORE the send. Add the requested slot to it when it differs.

**R1.7** **A stale registry entry must NOT count against the slot's task cap.** The bridge
already detects them (`[!] STALE tasks detected ... (started but never marked completed)`) and
prints the list - then counts them anyway. An entry whose lane is finished (its browser tab
is gone, its chat is closed, or it is older than a bounded age) must be EXCLUDED from
`is_slot_available()` / `active_tasks_for_slot()`. Today `/u/1/` (3), `/u/3/` (2) and `/u/9/`
(2) look busy although every one of those entries is from 2026-11-06/07.

**R1.8** The dispatcher's own `--open-browser --slot X` proof step must not count against X's
task cap either, and it must not leave a registry entry that outlives the browser tab.

**R1.9** When stale entries are ignored, the pool must be re-read from the LIVE browser
before a slot is declared busy - the signed-in state comes from `Default/Preferences`
(`account_info`), not from the registry.
